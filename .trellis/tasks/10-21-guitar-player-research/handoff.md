## 用户真正需求

直接导入 MP3/WAV，在《异环》明音凛演奏玩法中自动弹奏；用户没有音乐基础，不应要求找 MIDI、读谱或手工改谱。MIDI 可以作内部格式。

现有工具不满意的已确认原因只是要求提供 MIDI；不擅自推断它们音质差、不会翻页或必须全部重写。先验证音频识别听感，再决定怎样复用演奏端；不能把手工串联两个工具当作最终体验。

## 本轮实际结果

完整记录：`research/transcription-experiment.md`。

- 复用本机既有 `Pycode` 环境的 GPU PyTorch 2.7.1+cu128 所带 CUDA 12.8/cuDNN 9.7.1 DLL。已实测 CUDA 张量运算可用。
- 新建项目 `.venv-transcription`，Python 3.11.15，Basic Pitch 0.4.0、ONNX Runtime GPU 1.24.4；没有安装 TensorFlow、驱动或整套 CUDA，也没有修改原 conda 环境。
- resampy 0.4.2 需要 `pkg_resources`，已将本机既有 setuptools 76.1.0 只读复制到隔离环境；清单见私有 `research/audio-sample/reused-setuptools.json`。网络请求偶发 TLS EOF，不要反复空耗时间查询逐包元数据。
- Basic Pitch 使用 `--no-deps` 安装以避免 TensorFlow；ONNX所需依赖另行解析。`uv pip check` 仍报告1项元数据缺失（Basic Pitch在Python3.11强制声明TensorFlow），不能说依赖检查全绿；ONNX实际运行与产物检查已通过。
- Basic Pitch PyPI 0.4.0 写死 CPU，与之前阅读的上游主分支不同。研究脚本继承 Model 显式创建 GPU 会话，未修改第三方包；profiling 证明实际有 6748 个 CUDA 节点事件、140 个 CPU 节点事件。
- 已对《潮鸣》00:30–01:15、45秒安全片段实际转谱，得到 **450音**、MIDI29–100（F1–E7），最多同时8音。
- 相对截图键盘52–87，**136音（30.2%）超出音域**。没有把全曲简单转谱当作最终游戏适配。
- 同进程预热、交替顺序各三次：GPU热推理中位 **0.506秒**，CPU **0.862秒**；不含启动、后处理与合成导出。首次GPU `run_inference` 为24.659秒，其中模型调用1.056秒，其余含音频库冷启动等；不可混比冷热数据。
- CPU/GPU均450音、相同音高数量分布，但16个事件时间有差异；最大起始差11.61ms、结束差69.66ms。输出张量不满足绝对差0.001，不声称完全一致或有准确率保证。
- 原 MP3 SHA-256 与纳秒修改时间实验前后一致；只处理派生音频。
