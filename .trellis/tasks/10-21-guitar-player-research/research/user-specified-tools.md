# 用户指定的两个工具核查

## 范围与方法

用户明确不满意的是现有工具要求自行提供 MIDI，而不是已报告某项听感或操作缺陷。用户在 B 站看到两个工具，并提供一个 GitHub 发布页和另一个 B 站视频。

本次由主代理直接核查，无新增子代理。读取 GitHub README、发布页、GitHub API 仓库树与最新发布；读取 B 站视频元数据、作者评论，并使用已安装 FFmpeg 提取指定时间画面。没有下载/运行软件包、安装依赖或操作游戏。画面抽样不等于看完视频，也不构成本地软件功能测试。

## 1. DIEtype / Guitarplayer-For-NTE

来源：
- 用户链接：https://github.com/DIEtype/Guitarplayer-For-NTE/releases
- README：https://github.com/DIEtype/Guitarplayer-For-NTE
- API：https://api.github.com/repos/DIEtype/Guitarplayer-For-NTE/releases/latest
- 树快照：`01a36562fe89376395521f0921a702ce9d8e0d9d`

核查结果：
- API latest 为 **v0.11.7**，与 README 当前版本一致。
- README 声称 Windows 独立 EXE、无需 Python，可导入 MIDI 或图形手工编谱；有非鼓轨选择、移调、单音旋律与指弹近似、原谱和转译试听、曲库及停止释放输入。
- README 明确写 **四页 24 个和弦**，含分解拨弦、同拍多弦、上/下扫弦；还支持作者所称“品格”及和弦/品格混合演奏、自动 Z 切换、翻页准备间隔。因此它是此前宽泛检索漏掉的直接相关项目，不能继续说未找到支持和弦翻页的现成工具。
- v0.11.7 发布说明包括独立调度、重复输入松开余量、手柄翻页/选圆盘等。此类毫秒数是作者实现参数，不是本轮测得的游戏限制。
- README 写“曲谱、MIDI 和 WAV 试听文件保存在本地曲库”；这里的 **WAV 是试听输出**，不能据此推断支持输入 WAV/MP3 自动转谱。所核查 README 和最新发布说明没有找到成品音频转谱入口。
- 当前 main 树只见 README、`nte-guitar-player-v0.8.0.zip` 及其 SHA256；README 称旧 ZIP 为源码发布包。本轮未下载或检查该 ZIP。GitHub API license 为 null，树中未见 LICENSE。不能将“放在 GitHub”说成最新版本已完整开源或允许自由复制代码。
- 没有发现文档化的自动导入 MIDI 的 CLI/API，不能直接承诺外接转谱后就能无缝控制它；若选此路线，需另行核查接口与授权。

证据等级：作者说明与仓库元数据，不是当前版本源码实现验证或游戏实测。

## 对建议的修正

1. 需求痛点已明确：**用户不愿也不应先找 MIDI；普通歌曲必须成为直接入口。** 不应继续把“已有演奏工具不够好”泛化为尚未报告的播放质量问题。
2. 演奏端已有直接相关实现参照，尤其第一个工具已声明和弦翻页和混合演奏；完整重写全部演奏功能不应成为未经比较的默认方案。
3. 真正需先证明的是 **用户歌曲 → 能听出原曲的可演奏音符/和弦**。可在内部使用 MIDI，但用户不必读取或手工修复它。模型对整曲混音的质量仍需代表性歌曲测试。
4. 推荐先用用户最想弹的一首歌的短片段核查转谱听感，再根据接口、许可、校准负担与实际效果决定复用现有播放端还是独立实现。不会把“先自行导出 MIDI 再手工导入另一工具”当作最终用户体验。
5. 不承诺完整保留原曲的唱词、音色、鼓与所有声部。没有歌曲样本或转谱运行证据前不报准确率、处理速度和最终听感。
