# Windows《异环》自动演奏工具：已批准需求基线

> 状态说明（2026-10-21）：本PRD记录批准时的需求与验收基线，不是当前实现清单。整体方案已批准，任务处于 `in_progress`；当前实现与本机验证以 `handoff.md` 顶部为准。真实游戏操作仍待用户验证。

## 1. 目标与当前审批状态

让没有音乐基础的用户导入普通MP3/WAV歌曲，经本地自动处理与试听后，在Windows电脑版《异环》明音凛演奏界面自动演奏。不要求用户寻找MIDI、理解乐理、手工改谱或串联两个程序。

本任务由调研延续到产品实现。用户已对上一轮完整方案明确回复“可以，后面有问题我再说”，整体批准prd/design/implement与摘要，包含常规前台键盘/鼠标、本地校准截图及分页区域核对。现进入实施激活流程，按计划连续实现与验证；真实游戏校准仍由用户亲自执行，不能把本次批准当作游戏已经验收。

## 2. 已确认的用户决定

- 平台：Windows电脑版《异环》，不是手机或模拟器。
- 主要入口：普通歌曲文件；MIDI仅作内部中间格式。
- 听感目标：旋律清楚优先，伴奏允许简化；不固定为单声部，也不默认把所有识别声部混在一起。
- 用户反馈最新独立模型样本“虽然还是有点怪，但这个好像真的可以”：作为暂可接受的研究基线，保留残余缺陷，不代表所有歌曲或真实游戏效果通过。停止继续盲调94/122音失败候选。
- 用户接受普通前台模拟输入仍可能存在账号风险，并提供自己的 `combine_ark` 经验；此前未封禁不证明本游戏安全。
- 尽量减少子代理，主代理负责规划与统筹，不为机械检索或重复研究开启并行代理。
- 已批准项目隔离研究环境及开源转谱依赖/模型下载；不修改全局环境、不上传音频。产品环境准备和常规前台鼠标需求一并列入本次整体方案终审，不扩大到额外驱动或安全控制变更。

## 3. 已核查证据与边界

### 3.1 游戏界面

截图键盘模式有36个连续半音，标签E3–D♯6，对应标签换算MIDI52–87；三排分别使用 `A S D F G H J K L ; ' Enter`、`Q W E R T Y U I O P [ ]`、`1 2 3 4 5 6 7 8 9 0 - =`。不要照抄其他NTE工具的Shift/Ctrl布局。

和弦模式有四个分页圆点、R/T翻页；当前页可见G、Am、Bm、C、D、Em，中心六弦，V切音色、Z切模式。其余三页标签、每弦实际音高、选择和弦/扫弦动作、复音与时序未实测。现有工具作者说明支持四页24和弦，不等于本机游戏验证。

证据：本机 `research/user-screenshot-evidence.md`；公开可复用的键位事实亦记录在设计中，不分发个人截图。

### 3.2 音频研究与失败记录

| 事实 | 状态与记录 |
| --- | --- |
| 用户选《潮鸣》，原MP3约154.41秒、48kHz双声道，完整解码无错误 | 本机授权文件的路径/哈希见 `research/audio-sample-inspection.md`，原件未改；研究片段是00:30–01:15，不是歌曲最初45秒 |
| Basic Pitch0.4.0 + ORT GPU1.24.4识别450音，其中136音超出截图音域 | `research/transcription-experiment.md`；GPU实跑已确认，不能静默CPU回退 |
| 旧试听纯正弦波不适合判断乐器听感；改采样钢琴后用户确认明显清楚 | `research/whole-chain-review.md`；采样钢琴01未叠原曲，原样复算逐采样一致；仅标注左右对照的文件含原曲 |
| 默认剩余能量后处理额外补出77音；不能将其全判错音 | 同上；两次阈值降杂A/B失败，停止继续堆过滤 |
| 94音严格单线版、122音补衔接版均被用户否决 | `research/melody-priority-experiment.md`、`melody-continuity-correction.md`；前者截短22尾音，后者虽覆盖相同仍删除起音 |
| 第4–5秒具体失败：4.077–5.261秒只剩长音，4.461/4.868秒起音被删 | `research/attack-loss-diagnosis.md`；持续有音符不等于节奏/旋律正确，禁止机械填音掩盖问题 |
| 独立钢琴神经模型重新从音频识别，片段内272音、预测踏板，4.47/4.87秒起音保留 | `research/independent-neural-model-probe.md`；45秒转谱调用7.645秒、峰值CUDA分配约340MiB；28项机械测试通过，用户暂认可试听 |

最新模型是钢琴专用对照，不是声部分离器。首版沿用已认可的音符识别基线，仍接收普通歌曲；复杂混音可能效果不佳，必须明确提示并允许试听决定，不宣称任意歌曲完美还原，不再把找谱/改谱责任交给用户。

### 3.3 环境与已有工具

- 本机RTX4060 Laptop、显存8188MiB。既有Pycode环境Python3.10、PyTorch2.7.1+cu128/CUDA12.8/cuDNN9.7.1可用，张量与模型均已CUDA实跑。
- `.venv-transcription` 为Python3.11研究环境；Basic Pitch0.4.0发布包写死CPU，研究调用方显式GPU会话，未改第三方包或引入TensorFlow。旧Python3.12的CPU环境不能误当作可用GPU环境。
- `.venv-piano-probe` 为Python3.10隔离探测环境，只读复用既有GPU Torch，38项本地依赖检查通过。官方172MB级权重已下载且双哈希验证，**不重复下载或重装整套CUDA**。
- DIEtype/Guitarplayer-For-NTE作者声明四页24和弦、翻页/混合演奏，但最新源码/许可及自动导入接口未确认；寻枫椛V2.5/V3均未找到普通音频转谱证据。不能把WAV试听输出当作WAV输入能力。见 `research/user-specified-tools.md`。
- 其他4个相关项目和第三方作者页面的初轮核查见 `research/existing-tools-and-transcription.md`，不能把常见21/36键钢琴等同于当前截图映射。
- `combine_ark` 参考为Win32鼠标输入、F8急停及窗口身份校验；许可并非MIT，不能照搬游戏专用鼠标处理、固定等待或自动提权。见 `research/input-reuse-review.md`。

## 4. 产品要求

| ID | 要求 |
| --- | --- |
| R1 | 一体化导入MP3/WAV，处理整首歌曲，显示进度/取消/失败原因；用户不操作MIDI或命令行。 |
| R2 | 本地自动转谱，复用已验证模型与GPU环境；明确当前模型适用性和质量不确定性，不静默改用失败算法。 |
| R3 | 提供转谱试听与对应游戏适配效果试听；区分采样参考音色和游戏实音，不混原曲冒充识别效果；保留原起音/休止，适配损失可见。 |
| R4 | 键盘模式覆盖当前36个独立键、音域适配、同键重复/重叠、合理复音；无需用户理解移调或编写映射配置。 |
| R5 | 吉他模式包含四页24和弦、自动分页与选和弦/扫弦；是受游戏预设限制的和弦近似，不保证逐音还原。全部页和动作验证前不得标记完成。 |
| R6 | 限定用户选定的游戏前台窗口；采用常规Win32输入。键盘模式发按键，完整吉他模式需增加前台鼠标选区/扫弦，此点在本次终审明确批准。F8急停、暂停/失焦/异常/关闭释放本工具持有的键与鼠标按钮；不自动提权。 |
| R7 | 界面保持响应，转谱与演奏互斥；更换歌曲、取消任务、旧任务晚到、暂停恢复、退出均不得错播或卡键。 |
| R8 | 双击启动，本机复用环境/模型；不要求手工填写JSON或音乐参数。原歌曲只读，日志/缓存/校准均本地，用户文件不进入Git或云端。 |
| R9 | 实现后先完成离线自动化与工具自身UI验证，再集中请用户实际操作游戏校准/验收；记录每项未验证内容，不由AI操控游戏。 |

## 5. 非目标与明确限制

- 不实现云转谱、账号登录、录音上传、曲库市场、通用MIDI/六线谱编辑器、Guitar Pro导入或多游戏支持。
- 不读取/写入游戏内存，不DLL注入、不改游戏文件、不后台输入、不绕过反作弊或Windows安全限制，不安装虚拟手柄驱动。
- 不保证所有人声/混音歌曲准确；不以手动寻找MIDI、仅提供导入/试听界面或让用户串联两款软件代替自动演奏交付。
- 不保证当前模型预测踏板能在游戏内同样实现，不把源码/作者参数当作游戏延音或复音实测结果。
- 不把当前机器成功运行当作已完成独立安装包/所有Windows机器兼容；首版本机可用优先，不承诺未经测量的交付天数。
- 本次整体方案已获批准，允许范围内的产品代码、项目隔离依赖准备和工具本身验证；不由AI触发真实游戏输入。

## 7. 决策与审批清单

- 音频基线、Windows目标、普通前台模拟输入存在风险：用户已确认。
- 方案拟采用本地原生桌面界面、现成转谱模型、最小游戏输入适配，而非复制不明许可播放器或要求手动MIDI串联。
- 本次整体终审必须明确包括：吉他所需常规前台鼠标、全部两模式范围、模型效果边界、必要的项目内小依赖准备和用户亲自进行真实游戏校准。
- 上述整体方案已由用户明确批准，无需对普通实现步骤重复确认；没有遗留需另起一轮研究的产品意图问题。技术未知由实施验证关口承担，不能通过默默缩减R1–R9消除。
- 用户已授权GitHub仓库提交推送，但当前仍有未提交研究改动；本轮不推送、发布或创建外部PR。个人原音频、截图、抓取原文、测试环境及本地路径记录不发布。
