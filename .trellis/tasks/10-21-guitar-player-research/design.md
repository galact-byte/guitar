# 技术设计：Windows本地自动演奏工具

状态：整体方案已获用户明确批准，进入实现；本文件仍为设计契约，不是所有功能已经完成的记录。需求权威为 `prd.md` 的R1–R9/A1–A7。

## 1. 推荐方案与取舍

采用Python3.10、Tkinter/ttk原生桌面界面、独立转谱子进程、确定性游戏适配器、Win32前台输入调度。Tk8.6.14及所选本机字体已探测可用；不另装Web框架、浏览器运行时、Qt或虚拟手柄驱动。

默认沿用最新被暂认可的钢琴神经模型，不再调用94/122音筛选/补空隙流程。它接受普通音频但不保证复杂混音准确；不添加未经验证的自动声部分离。Basic Pitch旧实验保留作研究，不静默作为产品失败回退。

现有演奏端有参考价值，但DIEtype最新许可/自动导入接口不明确，其他工具的NTE键位与当前截图不一致。故只自研本界面的最小映射、前台输入、安全调度与一体化UI，不重建通用谱面编辑器或复杂播放器。`combine_ark` 用于参考Win32、F8和窗口身份设计，不照搬固定等待、自动提权或游戏专用鼠标扰动。

首版优先本机可运行，使用已安装GPU PyTorch和缓存模型；独立EXE/其他机器适配是后续打包问题，不作为跳过两模式真实验证的理由。

## 2. 模块边界与数据流

> 历史设计快照（2026-10-21）：以下结构是批准阶段的目标模块划分，不是当前文件清单；实现现状以 `handoff.md` 顶部和仓库工作树为准。

```text
guitar_player/
  app.py                 Tk界面和状态展示，不执行模型计算/计时循环
  jobs.py                子进程任务、取消、代际标识与缓存提交
  transcription.py       音频解码/模型接口/输出边界归一化
  arrangement.py         键盘或和弦计划及适配差异报告
  profiles.py            截图键位、已验证和弦表、图形校准数据
  preview.py             相同计划的离线采样与本地试听
  playback.py            单调时钟、暂停/恢复、停止、释放
  win_input.py           ctypes Win32窄接口，支持假设备注入
  storage.py             本地作业、缓存、原子写与日志
main.py / launch.py / start.bat
requirements.txt
profiles/                无个人坐标/路径的版本化游戏规则
assets/                  允许分发且已核对许可的小资产；不放模型/原曲
tests/                   纯测试和受控工具UI测试，不默认向游戏发输入
docs/development.md      开发/验证说明，README只讲普通用户操作
data/                    本机派生文件/日志/校准/模型索引，Git忽略
```

```text
普通歌曲（只读）
  → FFmpeg/解码器安全解码、采样率归一化
  → 独立模型子进程（已有GPU优先）
  → 原始Note/Pedal事件（识别结果不覆盖）
  → 所选游戏Profile适配
  → PerformancePlan + AdaptationReport
  ├→ 相同计划的采样试听
  └→ 前台身份/校准检查 → 倒计时 → 单调时钟调度 → SendInput
```

UI只接收带job_id的进度/结果，不导入GPU重库来阻塞Tk主线程。任一时刻仅一个转谱作业或演奏任务；试听和演奏互斥。

## 3. 内部数据契约

- `Note`：原生Python `float start/end`（秒）、`int pitch/velocity`。要求有限值、`0 <= start < end <= duration`、音高0–127、有效力度；拒绝NaN/布尔充数或不可序列化NumPy标量。踏板为显式CC64事件。
- `TranscriptionResult`：schema版本、歌曲哈希、模型哈希/版本、运行设备、有效音频时长、原始事件与诊断。上游padding之外事件明确裁掉，仅末端跨界尾音可裁齐，不删内部起音。
- `GameProfile`：schema/版本、模式、键位或四页和弦表、经确认的输入时序与复音限制、支持的动作、校准状态。只有验证过的字段标记verified，不使用臆造的24和弦或最大复音数。
- `PerformancePlan`：source/profile/settings哈希、模式、时长、按绝对时间排列的动作、初始状态前置条件、目标窗口身份引用。动作可为按键、鼠标选区/扫弦、分页、释放；同刻先必要释放与状态切换，再新起音。
- `AdaptationReport`：音域变化、合并/受限事件及理由、分页准备冲突、无法演奏的段落。不可可靠执行的计划明确失败或提示换模式，不能静默吞掉整段旋律。
- `WindowIdentity`：用户选定的HWND、PID及可读取的进程身份元数据；句柄/PID不符、窗口失效、最小化或前台不符都禁止新演奏动作。重启进程必须重新绑定。

设备、时钟、前台检测、文件系统边界可注入假实现。JSON采用UTF-8、原生数值及 `allow_nan=False`，写缓存前完成校验。

## 4. 音频与环境

- 项目产品环境优先Python3.10，隔离环境只读复用既有Pycode GPU Torch；研究环境 `.venv-piano-probe` / `.venv-transcription` 保留不破坏。实际依赖准备只限项目，不安装全局CUDA/TensorFlow。
- 复用已验证171966578字节权重，加载前核对SHA256，`weights_only=True`、严格state_dict匹配；缓存命中不再下载。缺模型不能以旧试听文件冒充新转谱。
- FFmpeg优先现有安装/PATH，参数列表调用、不使用shell拼接用户路径；中文/空格路径、失败退出、取消与超时须测试。解码得到的音频/时长有限，输入与资源上限在界面清楚提示。
- 默认GPU可用就使用并记录实际设备；不可用时说明原因，不静默降CPU或重新安装Torch。可提供明确选择的CPU模式，但需单独验证、不宣传未测速度。
- 《潮鸣》45秒实测7.645秒不含安装、导入、重采样与合成；完整154秒与其他歌曲耗时在实施时另测，不线性外推为交付保证。

## 5. 两种游戏适配

### 5.1 键盘模式：优先保留旋律与起音

标签音域52–87，三个八度逐半音映射：

| 音域 | 对应按键 |
| --- | --- |
| E3–D♯4 | A S D F G H J K L ; ' Enter |
| E4–D♯5 | Q W E R T Y U I O P [ ] |
| E5–D♯6 | 1 2 3 4 5 6 7 8 9 0 - = |

标点按键采用明确虚拟键/扫描码处理，不当作文本输入或依赖输入法。音域外优先寻找一致八度方案；不能整体容纳时，仅对越界音作最小八度折叠，保留音级/起音并报告变化。没有真实声部分离结果就不假称已分轨；不把任意高音全当杂音，也不按空白时间填音。

同一游戏键的重叠与重击需单独建模：新起音必须可触发，旧音的结束不能错误释放后来的按下；物理输入受限时明确报告近似。不要简单合并成长音抹去重复起音。最大复音/最小重击间隔要校准，不能照搬其他项目的6音或毫秒常量。

原识别事件保持不变，适配结果另存。原始转谱试听与游戏适配试听明确区分；4.47/4.87秒起音及整段瞬态作为回归证据，不将频谱检测当主旋律真值。

### 5.2 吉他模式：四页和弦近似

- 完整支持四页、每页六槽的已确认可用和弦；不是只做截图当前页。当前只确认一页G/Am/Bm/C/D/Em，其他标签和弦位须在实施校准关口取证。
- 从识别音符的节拍/和声音高集合匹配实际可用和弦，优先保持起拍；选区与R/T换页提前安排在发声前。扫弦是和弦近似，不能称为逐音还原主旋律。
- 和弦表、可用弦与页面切换规则来自游戏验证，不复制不明许可的播放器代码。开发阶段由用户提供/确认其余页面截图，我负责整理表；普通用户无需手填24个和弦名或JSON。
- 图形向导在所选游戏窗口本地校准圆盘/分页点；坐标存为客户区归一化位置，运行时重算屏幕坐标。客户区变化超出已验证规则则停播重新校准，不在旧坐标上盲点。
- 发送常规前台鼠标选择与扫弦、数字键拨弦及R/T分页；具体按钮、保持、分页方向/环绕需用户游戏实测。无需驱动或后台输入。
- 当前页优先通过已校准的四分页指示点检查；识别模糊或缺页规则就停止，不能假装已在目标页。暂停/失焦后使页面状态失效，恢复前重新核对，避免连续错页。
- 速度过快导致分页来不及，不爆发式赶帧：明确指出无法可靠适配并提供键盘模式/较慢演奏的图形选项，不要让用户改谱。

### 5.3 真实验证的责任

用户亲自打开游戏演奏界面并操作校准/测试；AI不启动游戏、不替用户发输入。工具自身图形、假设备、计划、文件与生命周期先本地验证完，再提供一次集中游戏检查流程。缺三页证据或实际动作未验证，吉他项保持未完成，不删除要求或填假数据。

## 6. 调度与输入安全

- `time.perf_counter`/单调时钟，按绝对deadline调度，不采用每音 `sleep(duration)` 累积漂移。等待可被F8/取消立即打断；迟到记录实际值，超过已验证预算停止而非向游戏补发堆积动作。
- 界面启动默认未武装；用户选歌/模式/窗口并主动开始后倒计时，每批发送前重新确认目标身份与前台。检测到失焦就暂停/释放，返回焦点不自动继续。SendInput不是绑定HWND的原子发送，检查与系统分发存在固有竞态，不承诺绝对零误发；以前台检查、可中断等待和F8降低风险。
- F8全局紧急停止（沿用用户旧工具习惯），F9开始/暂停/恢复，始终有可见按钮；热键冲突明确反馈，不默默失去急停。
- 维护本工具成功发送的按下键/鼠标按钮集合。停止、取消、暂停、关闭、发送异常、部分成功、目标身份改变走同一个幂等释放路径；不清理无关用户输入。失焦后仅允许尽力释放本工具已有按下，不发新的演奏动作。
- `SendInput`返回数量与结构体尺寸都核查；部分失败不能重放整组。拒绝输入/UIPI问题就停，不自动UAC、不改变认证/安全控制。
- 暂停后释放会打断尾音，继续仅按明确位置重建当前可恢复状态，并提示这一近似。吉他恢复必须重新确认页状态，不盲按Z猜模式。
- 所有单元/集成自动测试默认假Sender，实际SendInput仅由用户在工具明确武装时触发。崩溃/强制终止不作“绝对不会卡键”的承诺；常规异常/退出可测，文档给出手动松键说明。

## 7. 原生界面与用户流程

功能型、浅色Frost方向；无Hero、装饰数据、渐变卡片、乐理编辑器。单窗口四区：

1. 选择歌曲：文件、时长、处理状态、取消。
2. 演奏模式与目标窗口：键盘/吉他、校准状态，必要时进入图形向导。
3. 试听与演奏：默认试听适配结果；尚未校准时明确标成原转谱参考，禁止游戏演奏。开始/暂停/停止、进度与F8提示常驻。
4. 可折叠详情：音域适配/不可演奏提示、实际设备和打开日志位置，不要求普通用户调整阈值。

状态机：EMPTY → PROCESSING → READY → PREVIEWING或ARMED → PLAYING → PAUSED/STOPPED；任何阶段可进入ERROR。F8/取消使当前generation失效；旧子进程回来的成功结果不能覆盖新歌或自动播放。

转谱在独立子进程，Tk用after/队列更新；关闭先取消并回收子进程，再清理本应用资源，不留GPU工作/试听进程。子进程强制回收仅限本工具创建的作业，不杀其他Python/游戏进程。

视觉token：背景#f1f5f9、表面#f8fafc、文字#0f172a、主操作#0f766e、危险#b91c1c。标题“等线”加粗16pt，正文Microsoft YaHei UI 12pt，时间Cascadia Mono；本机字体已探测，无CDN。8px间距系统，关键按钮至少44逻辑像素，文字状态不只靠颜色，Tab/焦点可见。验证760/960/1280宽度和Windows缩放，长中文文件名不能遮住停止按钮。Tk原生控件采用对应的原生无障碍语义，不生搬HTML/移动端规则；无装饰动效。

## 8. 试听、存储与隐私

采样渲染明确是参考音色，不等于游戏音色。保留显式CC64二值踏板语义；渲染器只支持已验证控制，其他控制须拒绝而非静默丢弃。同刻先踏板、后松键/起音，踏板释放不截断再次按住的键。游戏是否有同等踏板能力单独验证，不将其作为实际发键动作臆造出来。

作业用UUID临时目录，成功后原子提交；缓存键含源音频哈希、模型/处理版本、profile及参数，试听还包含音色/渲染版本。取消或失败不覆盖已有成功缓存。模型、缓存、个人路径、校准截图只在Git忽略的data中保存，不自动删除原歌曲或旧研究资产；缓存清理须界面确认，只针对可再生数据。

校准截图只在用户主动操作向导时采集选定游戏客户区，本地保存。运行时仅在所选游戏前台且执行分页后，局部读取已校准的页码指示区域核对结果；不后台持续抓屏/录像、不上传、不读取其他窗口。这些行为与鼠标输入一并在整体方案披露。

日志记录阶段、设备、模型/profile版本、取消、迟到和停止原因；不自动采集原曲内容或对外发送。用户可自行选择提供诊断，不强制上传。
